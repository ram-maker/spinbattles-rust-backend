# SpinBattles Rust Web3 Assessment Guidelines

## Overview

This assessment evaluates practical Rust and Web3 development skills in a realistic gaming context. We want to see how you approach real problems, make tradeoffs, and communicate your decisions.

## Important Notes

1. **This is evaluation only** — This code is not used in production or for any commercial purpose. It exists solely to fairly evaluate candidates.

2. **Time-boxed** — The assessment is designed to take 2-3 hours. We respect your time and don't expect perfection.

3. **One task only** — You will be assigned ONE specific task file. Focus only on that task.

4. **Tradeoffs are expected** — We value practical judgment. It's okay to make reasonable tradeoffs and explain them.

5. **Communication matters** — Clear explanations of your approach are as important as the code itself.

## What We're Looking For

**Technical Competence**
- Can you implement the core functionality in idiomatic Rust?
- Do you understand Web3 / Solana concepts?
- Is your code clean, safe, and maintainable?

**Security Awareness**
- Do you consider security implications?
- Can you identify vulnerabilities?
- Do you validate inputs properly?

**Practical Judgment**
- Do you make reasonable tradeoffs?
- Can you prioritize what's important?
- Do you avoid over-engineering?

**Communication**
- Can you explain your decisions?
- Are your comments helpful?
- Is your documentation clear?

## What We're NOT Looking For

- Production-ready code with 100% test coverage
- Perfect, over-engineered solutions
- Spending more than 3 hours
- Implementing features outside your assigned task

## Evaluation Criteria

| Area | Weight |
|---|---|
| Code Quality (idiomatic Rust, error handling, structure) | 30% |
| Functionality (core features work, edge cases handled) | 30% |
| Security (input validation, awareness of vulnerabilities) | 20% |
| Communication (comments, summary, setup instructions) | 20% |

## Tips for Success

1. **Read your task file carefully** — Make sure you understand what's required
2. **Start with the high-priority items** — Focus on what matters most
3. **Test your work** — Make sure it actually compiles and runs
4. **Explain your decisions** — Add comments and write a brief summary
5. **Don't overthink it** — We want to see practical skills, not perfection

## Submission Checklist

- [ ] Completed the high-priority tasks in your assigned task file
- [ ] Code compiles without errors (`cargo build`)
- [ ] Added comments explaining key decisions
- [ ] Written a brief summary (3-5 sentences)
- [ ] Included commands for testing your changes
- [ ] Stayed within the 2-3 hour time estimate

## Common Questions

**Q: Can I add crates to Cargo.toml?**
A: Yes, reasonable dependencies are fine. Explain why you chose them.

**Q: Should I write tests?**
A: Not required for Backend/Security/DevOps/Fullstack tracks, but a few key tests are a plus. Required for Smart Contract track.

**Q: What if I can't finish everything?**
A: That's okay. Focus on high-priority items and explain what you would do with more time.

**Q: Can I refactor existing code?**
A: Yes, if it helps accomplish your task. Explain what you changed and why.

**Q: Should I deploy to devnet?**
A: Not required. Local testing with `solana-test-validator` is fine.

## After Submission

1. We'll review your code (typically 2-3 business days)
2. If it looks good, we'll schedule a short review discussion (30 minutes)
3. In the discussion, we'll ask about your approach and decisions
4. This is also your chance to ask questions about the role and team
